# Notebook — Telegram-бот онлайн-записи

Notebook — учебный проект Telegram-бота на Python и Aiogram для записи клиентов к
специалистам. Две текущие командные задачи находятся **в процессе разработки**. В состав
каждой задачи входят интерфейс и связанная с ним логика.

Для локального запуска без базы данных предусмотрен режим с данными в памяти процесса.
Созданные в этом режиме бизнесы, настройки и избранное исчезают после перезапуска.

**Для участников команды:** [скачивание проекта, ветки, коммиты и Pull Request](docs/BRANCH_WORKFLOW.md).

## Сценарии, входящие в текущие задачи

- команда `/start` и возврат в главное меню;
- разделы «Мои записи» и «Мои специалисты»;
- список из одного или двух бизнесов пользователя;
- диалог создания бизнеса;
- профиль бизнеса для мастера и клиента;
- клиентская ссылка и публичный код бизнеса;
- поиск специалиста по коду и список избранных специалистов;
- включение и отключение приёма новых записей;
- изменение основных настроек бизнеса;
- понятная заглушка для разделов, которые относятся к следующим задачам.

## Задача 1 — главное меню и профиль бизнеса

**Статус:** в процессе разработки.

**Подробная постановка и приёмка:** [docs/TASK_1_MENU_BUSINESS.md](docs/TASK_1_MENU_BUSINESS.md).

**Основные файлы:**

- `src/notebook_bot/bot/menu.py`;
- `src/notebook_bot/bot/business.py`.

### Интерфейсная часть задачи

В задачу входят команда `/start`, главное меню, кнопки бизнесов, FSM-форма создания
бизнеса, профиль специалиста, настройки, поиск по коду, избранное и переходы к следующим
разделам. Telegram-обработчики отвечают за тексты, кнопки, состояние диалога и навигацию.

### Логическая часть задачи

В задачу входят получение пользователя, подготовка данных главного меню, создание не более
двух бизнесов, проверка владельца, получение профиля, изменение настроек и работа с
избранным. Интерфейс вызывает эти операции через объект `Catalog` и не обращается к файлам
или SQL напрямую.

## Задача 2 — модели данных и временное хранилище

**Статус:** в процессе разработки.

**Подробная постановка и приёмка:** [docs/TASK_2_MODELS_STORAGE.md](docs/TASK_2_MODELS_STORAGE.md).

**Основные файлы:**

- `src/notebook_bot/models.py`;
- `src/notebook_bot/storage.py`.

### Интерфейсная часть задачи

Интерфейс получает подготовленные объекты пользователя, бизнеса, услуги, клиента и записи
через сервисный слой. Формат этих объектов определяет, какие сведения можно показать в
меню, профиле и будущих карточках. Telegram-слой не должен знать, сохраняются данные в
памяти, JSON или SQL Server.

### Логическая часть задачи

В задачу входят модели предметной области, связи через `business_id`, операции `get`,
`list`, `put` и `delete`, транзакционное обновление данных, режим памяти и временное
JSON-хранилище. В будущем тот же контракт должен поддержать адаптер Microsoft SQL Server.

## Точка запуска и вспомогательный код

`src/notebook_bot/main.py` создаёт объект приложения, подключает middleware, FSM и роутеры,
после чего запускает long polling Telegram. Неизвестные callback будущих разделов
обрабатываются общей заглушкой, поэтому нажатие на такую кнопку не приводит к падению.

`src/notebook_bot/config.py` читает токен, внутренний часовой пояс и параметры будущего
хранилища из `.env`.

Для связи интерфейса и логики используются:

- `bot/common.py` — общие клавиатуры, отправка сообщений, FSM-формы, middleware и
  обработка ожидаемых ошибок;
- `logic/catalog.py` — сервисные методы для связи экранов с логикой;
- `logic/rules.py` — минимальные преобразования ввода, необходимые общим формам.

## Архитектура текущей версии

```text
Пользователь Telegram
        ↓
Telegram Bot API
        ↓
main.py → Aiogram Dispatcher
        ↓
bot/menu.py и bot/business.py
        ↓
logic/catalog.py
        ↓
временные данные в памяти процесса
```

| Часть | Ответственность |
|---|---|
| `bot` | Telegram-команды, callback, сообщения, клавиатуры и FSM |
| `logic` | Сценарии приложения и бизнес-правила без зависимости от Telegram |
| `models.py` | Модели всей предметной области |
| `storage.py` | Разрабатываемый временный адаптер памяти и JSON |
| `database` | Будущий адаптер Microsoft SQL Server |
| `main.py` | Сборка зависимостей и запуск приложения |
| `config.py` | Загрузка локальной конфигурации |

## Как скачать проект в Visual Studio Code

1. Установить [Git](https://git-scm.com/downloads) и Python 3.12 или новее.
2. Перезапустить Visual Studio Code после установки Git.
3. Нажать `Ctrl + Shift + P` и выбрать `Git: Clone`.
4. Выбрать **Clone from GitHub** и авторизоваться аккаунтом, которому выдан доступ.
5. Выбрать `pupue67/Notebook`, затем папку на компьютере и нажать **Open**.

То же действие через терминал:

```powershell
git clone https://github.com/pupue67/Notebook.git
cd Notebook
code .
```

Для приватного репозитория GitHub потребует авторизацию. Подробное создание отдельной
ветки и Pull Request описано в [инструкции для команды](docs/BRANCH_WORKFLOW.md).

## Как установить и запустить бота

Рекомендуемые расширения Visual Studio Code:

- **Python** от Microsoft;
- **Pylance** от Microsoft.

Откройте терминал в корне репозитория и создайте виртуальное окружение:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
```

Если PowerShell запрещает запуск сценария активации, выполните в текущем окне:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

Создайте локальный файл настроек:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и замените пример токена на новый токен, полученный через BotFather:

```env
BOT_TOKEN=put_your_new_token_here
STORAGE=memory
DATA_FILE=data/notebook.json
CITY_TIMEZONE=Asia/Yekaterinburg
BOT_PROXY=system
```

Запустите бота из корня репозитория:

```powershell
python -m notebook_bot.main
```

После появления сообщения о polling откройте бота в Telegram и отправьте `/start`.
Остановка выполняется сочетанием `Ctrl + C`. Временные демонстрационные данные после этого
удаляются.

## Быстрая проверка интерфейса

1. Отправить `/start`.
2. Начать создание бизнеса и проверить кнопки «Назад» и «Отмена».
3. Создать первый и второй бизнес и открыть каждую кнопку в главном меню.
4. Убедиться, что действие создания третьего бизнеса больше не показывается.
5. Открыть профиль мастера и клиентский вид.
6. Изменить настройку и переключить приём новых записей.
7. Открыть раздел «Мои специалисты», выполнить поиск по коду и изменить избранное.
8. Нажать кнопку будущего раздела и проверить понятное сообщение-заглушку.

## Безопасность токена

Файлы `.env`, пользовательские данные, журналы и токены не добавляются в Git. Если токен
попал в сообщение, снимок экрана, коммит или открытый репозиторий, его нужно отозвать через
BotFather и создать новый.
