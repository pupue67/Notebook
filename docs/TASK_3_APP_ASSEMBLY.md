# Задача 3. Сборка, конфигурация и запуск приложения

## Статус

**В процессе разработки.**

## Цель

Собрать готовые части Notebook в запускаемое приложение: загрузить настройки, выбрать
memory- или JSON-хранилище, создать сервисный слой, передать его Telegram-обработчикам и
запустить Aiogram polling. Будущие разделы должны показывать понятную заглушку, а не
приводить к ошибке.

## Основные файлы задачи

```text
src/notebook_bot/main.py
src/notebook_bot/config.py
src/notebook_bot/repository.py
```

Задача не изменяет `bot/menu.py`, `bot/business.py`, `models.py`, `storage.py`,
`bot/common.py`, `logic/catalog.py` и `logic/rules.py`: эти файлы принадлежат задачам 1, 2
и 4.

## Что требуется реализовать

### Конфигурация

- загрузка `BOT_TOKEN`, `STORAGE`, `DATA_FILE`, `CITY_TIMEZONE` и `BOT_PROXY` из `.env`;
- отказ от запуска при отсутствующем токене;
- поддержка `STORAGE=memory` и `STORAGE=json`;
- отсутствие токена и пользовательского JSON в Git.

### Сборка зависимостей

- создание `MemoryRepository` без файла для режима memory;
- передача `DATA_FILE` для режима JSON;
- создание `Catalog` поверх Repository через контракт задачи 4;
- подключение готового `ContextMiddleware` из задачи 4;
- подключение `business.router`, `menu.router` и готового `forms_router` в правильном порядке;
- общий fallback для ещё не реализованных разделов.

### Запуск

- создание `Bot` и `Dispatcher`;
- запуск long polling;
- корректное завершение по `Ctrl+C`;
- запрет второго локального процесса с тем же JSON;
- понятная ошибка при установленном webhook;
- скрытие токена в журнале непредвиденных ошибок.

### Контракт Repository

`repository.py` описывает протоколы `Repository` и `Transaction` с операциями `get`,
`list`, `put`, `delete` и транзакционным контекстом. Контракт не зависит от Telegram,
JSON или SQL Server.

## Критерии готовности

- `python -m notebook_bot.main` запускает polling;
- `/start` открывает главное меню;
- общие компоненты задачи 4 подключаются без циклических импортов;
- неизвестная кнопка показывает заглушку уровня приложения;
- `STORAGE=json` создаёт файл и восстанавливает данные после перезапуска;
- `STORAGE=memory` не создаёт пользовательский JSON;
- второй процесс не получает доступ к тому же локальному файлу;
- Telegram-обработчики не создают Repository самостоятельно;
- код не импортирует незавершённые модули записей, календаря и уведомлений.

## Проверка результата

1. Установить проект командой `python -m pip install -e .`.
2. Создать `.env` на основе `.env.example`.
3. Запустить `python -m notebook_bot.main`.
4. Открыть `/start` и выполнить создание бизнеса.
5. Остановить и повторно запустить процесс.
6. Проверить восстановление бизнеса из `data/notebook.json`.
7. Нажать кнопку будущего раздела и проверить сообщение-заглушку.
8. Убедиться, что `main.py` использует `bot/common.py`, но не содержит реализацию общих
   клавиатур, FSM-форм и middleware.
