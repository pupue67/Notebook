# Задача 1. Главное меню и профиль бизнеса

## Статус

**В процессе разработки.**

## Цель

Разработать первый законченный Telegram-сценарий Notebook: пользователь открывает бота,
видит свои клиентские разделы и бизнесы, создаёт бизнес, открывает его профиль, меняет
основные настройки и может найти другого специалиста по коду.

Один пользователь может быть клиентом и мастером одновременно. Отдельное переключение
ролей в интерфейсе не требуется.

## Основные файлы задачи

```text
src/notebook_bot/bot/menu.py
src/notebook_bot/bot/business.py
```

`menu.py` отвечает за первый экран и передачу навигации. `business.py` отвечает за
создание, просмотр и настройки бизнеса, клиентский профиль, поиск и избранное.

## Вспомогательные зависимости

Для связи интерфейса и логики задача использует:

- `bot/common.py` — кнопки, отправка сообщений, FSM-формы и обработка ошибок;
- `logic/catalog.py` — сервисные методы пользователей, бизнесов и избранного;
- `logic/rules.py` — минимальные преобразования ввода для форм;
- `models.py` — `User`, `Business`, `Service` и `Favorite`;
- `storage.py` — разрабатываемый адаптер постоянного хранения;
- `main.py` — подключение роутеров к Aiogram Dispatcher;
- `config.py` — токен и режим хранения.

Telegram-обработчики не читают JSON и не выполняют SQL-запросы напрямую.

## Интерфейсная часть задачи

Интерфейсная часть включает Telegram-тексты, клавиатуры, callback, FSM-состояния,
навигацию и представление результатов логики пользователю.

### Экран `/start`

Без созданного бизнеса:

```text
Notebook

Выберите нужный раздел.

[  Мои записи ]
[  Мои специалисты ]
[  Создать бизнес ]
```

С одним бизнесом:

```text
Notebook

Выберите нужный раздел.

Мой бизнес:
[ Мои записи ]
[ Мои специалисты ]
[ Логопед Анна ]
[  Создать бизнес ]
```

С двумя бизнесами отображаются две независимые кнопки, а создание третьего скрывается.
Сервис повторно проверяет лимит, поэтому старый callback также не создаст третий бизнес.

### Главное меню

- команда `/start` без deep link;
- возврат по callback `home`;
- очистка незавершённого FSM при возврате;
- получение `MainMenuData` через сервис;
- динамическое отображение бизнесов;
- передача переходов другим роутерам через короткие callback.

### Создание бизнеса

Форма последовательно собирает:

1. название бизнеса;
2. имя специалиста;
3. краткое описание;
4. формат работы;
5. адрес или инструкцию подключения;
6. общий комментарий клиентам.

После сохранения пользователь получает переходы к первой услуге, рабочей неделе и
управлению бизнесом.

### Управление бизнесом

Владелец видит:

- название, специалиста, описание и адрес;
- услуги;
- клиентскую deep link;
- код профиля;
- состояние приёма новых записей;
- переходы к услугам, рабочей неделе, календарю, записям и клиентам;
- основные и расширенные настройки;
- просмотр профиля глазами клиента.

### Клиентский профиль

Клиент видит публичную информацию, активные услуги и действие записи. Когда приём новых
записей выключен, профиль сохраняется, но действие записи не показывается.

### «Мои специалисты»

- пустое состояние списка;
- поиск по коду;
- открытие найденного профиля;
- добавление и удаление бизнеса из избранного;
- отдельные элементы для двух бизнесов одного владельца.

## Логическая часть задачи

Логическая часть включает создание пользователя в контексте приложения, подготовку
главного меню, ограничение количества бизнесов, поиск профиля, проверку владельца,
изменение настроек и избранное. Интерфейс вызывает эти операции через `Catalog`.

## Границы ответственности

В задачу входят:

- Telegram-тексты;
- клавиатуры;
- callback;
- состояния форм;
- навигация;
- преобразование результатов сервиса в понятные сообщения;
- сервисные операции главного меню, бизнеса, настроек и избранного.

В задачу не входят:

- расчёт свободного времени;
- создание записи;
- SQL Server;
- реализация календаря месяца;
- отправка фоновых уведомлений;
- изменение внутренних правил хранения.

## Контракт интеграции

`menu.py` вызывает:

```text
app.get_main_menu_data(telegram_user_id)
```

`business.py` использует методы:

```text
app.business(...)
app.services(...)
app.create_business(...)
app.update_business(...)
app.favorites(...)
app.favorite(...)
app.owned_business(...)
```

Объект `app` передаётся через `ContextMiddleware`. Идентификатор `actor` определяется по
Telegram-пользователю на сервере; присланный callback не считается доказательством прав.

## Обработка ошибок

Проверяются:

- попытка создать третий бизнес;
- неизвестный бизнес;
- открытие управления чужим бизнесом;
- неверный формат настройки;
- пустой или слишком длинный текст;
- устаревшая кнопка;
- повторное добавление или удаление избранного;
- сообщение не из личного чата.

Ожидаемые нарушения проходят через `RuleError`. Пользователю не показываются traceback,
структура JSON, внутренний SQL или токен.

## Проверка результата

1. Отправить `/start` без бизнеса.
2. Создать первый бизнес и проверить его кнопку.
3. Перезапустить бот и убедиться, что временные данные очистились.
4. Создать второй бизнес и проверить две отдельные кнопки.
5. Проверить отсутствие создания третьего бизнеса.
6. Открыть профиль владельца и профиль клиента.
7. Выключить новые записи и проверить клиентский экран.
8. Найти бизнес по коду со второго аккаунта.
9. Добавить и удалить его в «Моих специалистах».
10. Проверить «Назад», «Отмена» и старую кнопку формы.

## Критерии готовности

- `/start` всегда открывает корректное меню;
- один и два бизнеса отображаются независимо;
- третий бизнес нельзя создать через интерфейс или старый callback;
- форма создания сохраняет полный профиль;
- владелец не может управлять чужим бизнесом;
- клиентский профиль не раскрывает внутренние данные;
- избранное не создаёт дубликаты;
- обработчики не читают хранилище напрямую;
- интерфейс не зависит от конкретного способа постоянного хранения;
- токен и `.env` отсутствуют в коммитах.
