## Цель

Мастер настраивает услуги, обычную рабочую неделю и отдельные даты. Клиенту позже
показываются только даты и времена, в которые помещается выбранная услуга. Каждый из двух
бизнесов владельца имеет собственные услуги и расписание.

## Что реализовать

1. Экран услуг выбранного бизнеса: список, создание, изменение цены, фиксированной или
   персональной длительности, скрытие услуги. Клиент не видит скрытые услуги.
2. Рабочую неделю из семи дней. День может содержать несколько непересекающихся
   интервалов, лимит клиентов и комментарий. Разрыв между интервалами означает регулярный
   перерыв.
3. Экран конкретной даты: разовые интервалы, закрытые части дня без причины, лимит,
   комментарий, адрес, выходной, ссылка на обычный график дня недели и ручную запись.
   Изменение даты не меняет другие недели.
4. Месячную сетку выбора последней даты самостоятельной записи с навигацией по месяцам.
   Дата хранится у бизнеса; после неё свободные слоты не выдаются. Пустые клетки не
   выполняют действие. Проверку права владельца делать на сервере, а не по виду кнопки.
5. Расчёт доступности: шаблон недели с переопределением даты, закрытые промежутки,
   существующие записи и общий перерыв между клиентами, длительность услуги, кратность
   начала, минимальный срок, горизонт и лимит записей. Клиенту показывать только
   свободные варианты без объяснения внутреннего лимита.
6. После изменения графика сохранять существующие записи и возвращать список конфликтов
   с действиями для просмотра или переноса.


## Критерии готовности

- Два бизнеса одного мастера могут иметь разные услуги и расписания на одну дату.
- Интервалы `10:00–13:00` и `15:00–20:00` оставляют обед недоступным.
- Разовое изменение среды не меняет следующую среду.
- Закрытие `16:30–17:30` не уничтожает существующую запись и показывает конфликт.
- Лимит скрывает заполненную дату для новых клиентов.
- Выбор конечной даты через календарь ограничивает выдачу свободных слотов и сохраняется
  после перезапуска с JSON.
- Недоступный или чужой бизнес нельзя изменить через поддельный callback.

## Проверка

Проверить услуги и слоты двух бизнесов, исключение даты, дневной лимит, закрытый
промежуток, конечную дату календаря и восстановление из JSON. Запустить `pytest` и Ruff;
зафиксировать ручной сценарий кнопок в Pull Request.
