# Как создать ветку и передать изменения на проверку

После принятия приглашения каждый участник сможет создать **свою ветку**. Проще всего сделать это через Visual Studio Code.

## 1. Сначала скачать репозиторий

Если Git ещё не установлен, нужно установить [Git](https://git-scm.com/downloads) и перезапустить VS Code.

Затем в VS Code:

1. Нажать `Ctrl + Shift + P`.
2. Ввести `Git: Clone`.
3. Выбрать **Clone from GitHub**.
4. Авторизоваться в GitHub, если VS Code попросит. Использовать аккаунт, который принял приглашение.
5. Выбрать репозиторий `pupue67/Notebook`.
6. Выбрать папку на компьютере.
7. Нажать **Open**, чтобы открыть скачанный проект.

Также можно открыть терминал VS Code и выполнить:

```bash
git clone https://github.com/pupue67/Notebook.git
cd Notebook
```

Скачивать репозиторий заново перед каждой работой не нужно.

## 2. Создать свою ветку

В левом нижнем углу VS Code находится название текущей ветки, после клонирования — `main`.

1. Нажать на `main` в левом нижнем углу.
2. Выбрать **Create new branch...**.
3. Ввести название ветки.
4. Нажать Enter.

Рекомендованные названия:

- `feature/calendar` — для задачи с календарём;
- `feature/database` — для задачи с базой данных.

После создания в левом нижнем углу вместо `main` должно отображаться название своей ветки, например `feature/calendar`.

То же самое через терминал для календаря:

```bash
git switch -c feature/calendar
```

Или для базы данных:

```bash
git switch -c feature/database
```

Нужно выполнить только команду для своей задачи. Если ветка уже существует, повторно создавать её не нужно: порядок продолжения работы описан ниже.

## 3. Внести изменения и создать коммит

После редактирования файлов открыть в VS Code раздел **Source Control** — значок управления исходным кодом слева.

1. Проверить список изменённых файлов и сами изменения.
2. Нажать `+` рядом с нужными файлами. **Stage All Changes** использовать, если все изменения относятся к задаче и должны попасть в коммит.
3. Написать понятное сообщение коммита.
4. Нажать **Commit**.

Примеры сообщений:

```text
Add monthly booking calendar
```

```text
Add initial SQL Server database schema
```

Через терминал это выглядит так, если все проверенные изменения нужно включить в коммит:

```bash
git add .
git commit -m "Add monthly booking calendar"
```

Если при первом коммите Git просит указать автора, выполните команды со своими данными:

```bash
git config user.name "Ваше имя"
git config user.email "Ваша почта GitHub"
```

Затем повторите коммит. Эти команды задают автора для этого репозитория. Можно использовать адрес `noreply` из настроек электронной почты GitHub.

## 4. Отправить ветку на GitHub

После первого коммита VS Code предложит кнопку **Publish Branch**. Нужно нажать её — ветка появится на GitHub.

Через терминал для календаря:

```bash
git push -u origin feature/calendar
```

Для базы данных:

```bash
git push -u origin feature/database
```

Параметр `-u` связывает локальную ветку с веткой на GitHub. В следующие разы после новых коммитов будет достаточно:

```bash
git push
```

Коммит сохраняет изменения локально, а `push` отправляет их на GitHub.

## 5. Создать Pull Request

После публикации ветки откройте [репозиторий Notebook](https://github.com/pupue67/Notebook). GitHub обычно показывает кнопку **Compare & pull request**.

Если кнопки нет, откройте **Pull requests → New pull request**.

Укажите:

- **base:** `main`;
- **compare:** свою ветку, например `feature/calendar`;
- название изменений;
- краткое описание выполненной работы;
- способ проверки.

Затем нажмите **Create pull request**.

Pull Request нужен, чтобы сначала проверить изменения и только потом добавить их в `main`. Пока Pull Request не объединён, основная ветка проекта не меняется.

Если после проверки нужно что-то исправить, внесите исправления в той же ветке, создайте новый коммит и выполните `git push`. Изменения появятся в уже открытом Pull Request.

## 6. Как начинать следующую работу

Перед созданием ветки для **новой задачи** обновите `main`. Сначала завершите и сохраните текущие изменения коммитом, чтобы не переносить незавершённую работу между ветками.

```bash
git switch main
git pull --ff-only
git switch -c feature/new-task
```

Вместо `feature/new-task` укажите название новой задачи. `--ff-only` обновляет ветку без автоматического создания коммита слияния. Если команда сообщает об ошибке, передайте её текст на разбор ответственному за интеграцию.

Если ветка уже существует локально, опубликована и работа продолжается:

```bash
git switch feature/calendar
git pull --ff-only
```

Для базы данных замените `feature/calendar` на `feature/database`. Эта команда получает изменения своей ветки с GitHub; новые изменения из `main` она автоматически не переносит.

Если ветку создали на GitHub, но на компьютере её ещё нет:

```bash
git fetch origin
git switch --track origin/feature/calendar
```

Замените название на свою ветку. Если локальная ветка уже есть, используйте обычный `git switch` из предыдущего примера.

**Главное правило: не работать напрямую в `main` и не объединять Pull Request без проверки.**
